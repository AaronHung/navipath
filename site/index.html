NaviPath-CL: A Continual Navigation Layer
for Agentic Whole-Slide Image Diagnosis

WSI 持續學習不只是學「怎麼分類」，更是學「怎麼看」。在 budgeted / agentic 病理診斷下，navigation policy（導覽策略）本身也會 catastrophic forgetting（災難性遺忘）。

在取得醫師實際瀏覽軌跡與 RLHF 資料之前，我們把 WSI 導覽抽象為在預先算好的 CONCH 特徵上做 budgeted patch selection，並以 QPMIL-VL 作為 frozen 的 prompt/prototype-based 診斷 backbone。核心問題：哪一種 continual mechanism 適合這樣的 navigation policy？

02問題設定

既有 WSI-CL 只處理 classifier forgetting，沒人處理 navigation-policy forgetting。

  • 現行 patch-by-patch / encode-all 把運算花在非重要區域，且非關鍵區域特徵會干擾診斷；醫師行為是「低倍率找標的 → 高倍率細看」。
  • 既有仿醫師方法未用醫師實際軌跡，靠弱監督 / 報告找區域，可能找錯目標或幻覺。
  • 新問題：有限 observation budget 下，agent 學新癌種後，還記不記得舊癌種「要看哪裡」？

03Mechanism Selection for Continual WSI Navigation

本節不是「列四個方法」，而是回答一個設計問題：Which continual mechanism is suitable for a WSI navigation agent?

Q1: Can a single shared navigation policy continually learn all tasks? → No. Works for recent tasks but fails on old tasks. Q2: Can standard weight-level CL regularization (EWC) fix this? → Not sufficiently. Old-task navigation remains weak. Q3: Is the old navigation skill fundamentally lost? → No. Per-task skill memory recovers old-task performance. Conclusion: The issue is not lack of diagnostic signal, but lack of continual navigation memory.

07Scope statement（誠實邊界）

務必寫進報告，避免過度宣稱。

邊界

  • 只實例化一個 backbone（QPMIL-VL）；跨 CL 家族列 future。
  • navigation = budgeted patch selection（Phase-0）；尚無 zoom / move、多尺度、醫師軌跡、真 RLHF。
  • reward = WSI label / QPMIL confidence（doctor-trajectory-unavailable 的 proxy）。
  • Context gate 用 oracle（task id）作 upper bound；task-free gate 列 future。

Do not claim

  • full physician imitation
  • task-free routing solved
  • compute saving under encode-all
  • raw WSI browser agent / complete RLHF
  • parameter merging solved
