答辯筆記：必須理解才能守護的觀念

被老師/reviewer 問時的完整底稿，持續添增。來源：docs/wiki/07~09。點標題展開。藍＝我們在做什麼（N2）、綠＝N3 分析、紫＝ZeroSlide / 老師疑慮。

一、我們在做什麼（N2 在驗證什麼）· wiki 07
一句話：我們到底在做什麼？

在一個凍結的病理 VLM backbone（QPMIL-VL = CONCH patch encoder + 文字分類頭）之上，外掛一層獨立的 Continual Navigation Layer。它回答：

當模型「一個癌症接一個癌症」依序學會 4 種癌症後，對最早學的那個癌症，還能不能正確地在整張 WSI 上知道「該看哪些 patch」？

我們發現「看哪」這能力會被後面任務覆蓋（遺忘），並用 per-task skill memory（NSM）救回。

seq vs oneshot？單步還是多步？
  • budget：一張 WSI 最多准看幾個 patch（16/32/64/128/All）。
  • one-shot（單步）：一次對所有 patch 打分，直接挑最高 K 個。
  • sequential（多步）：分多輪，每輪挑幾個 → 更新 Observation State（已看 patch 的彙整）→ 在「已看內容」基礎上對剩餘 patch 重評（加 redundancy 懲罰）再挑。＝ agentic「邊看邊決定下一步」。

oneshot＝單步選擇；sequential＝多步、有狀態的選擇。兩個都跑，是要證明「多步＋狀態」有沒有額外好處。

這是 Agent 還是 CL？
軸管什麼模組
Agent一張片內怎麼看、何時停Sequential Budgeted Observation + Observation State
CL學新癌症後，舊癌症還會不會看Navigation Skill Memory (NSM) + Context Gate

一句話：Agent 管「一張片內怎麼看」，CL 管「跨癌症別還記不記得怎麼看」。

router 跟以前的 selector / per-task 一樣嗎？
  • 零件沿用：router 本體是 MicroRouterV0（小 MLP，輸入 = patch 特徵 + 4 個 summary 統計）。
  • 架構全新：舊 selector 只做 one-shot top-K（單步、無記憶）；現在把同一 router 包進 Sequential Observer（多步＋狀態）＋ NSM（每任務存一份權重）＋ Context Gate。

擋 reviewer 用：舊 selector 是我們新框架的退化特例（oneshot + no-memory）；貢獻是外面那層 sequential + skill memory。

CL 怎麼設計？核心結果撐得住嗎？

依序訓練 4 任務 router，每學完一個就把權重快照存進 NSM；推論時 Context Gate（Phase-0 用 oracle = 已知任務 id）取對應 skill 再 navigate。對照組 nonsm 只留「學完 lung 後」那份 router（無記憶）去看 esca。

640.133（主動選錯＝災難性遺忘）0.867（救回）

問題存在（遺忘）＋ 我們的 memory 解決它 → CL 軸站得住。（nonsm@64=0.133 與舊版獨立驗過一致，重現無誤。）

為什麼只測 esca？lung 會慢幾十倍嗎？
  • 訓練階段 4 種癌症全部都訓練了（esca/rcc/brca/lung 各 5 epoch）。一個 fold ~3 小時幾乎全在訓練這 4 個 router。
  • 評估只測 esca：它最早學、最易被後面覆蓋，是遺忘最關鍵的觀察點；且 esca test 只有 15 張，eval 很快。
  • inference 很便宜（打分→選 K→一次前傳），測 lung 不會慢幾十倍。慢的是訓練，且訓練已做完、存進 skill bank。
  • N3 直接用同一 skill bank，把 task_index 換 1/2/3 eval rcc/brca/lung，不必重訓就能補成完整 4 任務 retention 表。
★ 沒有「醫生看哪裡」標註，router 怎麼學會看哪？（弱監督）

我們完全沒有 patch-level / gaze 標註，只有整張片的診斷 label。訓練流程：

  • ① router 對所有 patch 打分；② 取最高 K 個，softmax 權重加權聚合成 bag 向量；③ bag 丟進凍結的 QPMIL 文字分類頭得 logits；④ 跟整張片 label 算 cross-entropy，梯度只回傳到 router。

關鍵在④：router 挑的 patch 聚合後讓分類正確則 loss 低，挑錯則高。為降 loss，router 被迫學會「把對診斷有判別力的 patch（病灶區）打高分」。沒人告訴它哪裡是腫瘤，它從『我挑了這些→診斷對不對』的回饋自己學出來（weakly-supervised / attention-MIL）。

Policy 例子：學 esca 時把 esca 病灶紋理打高分→分類成功→被強化；換看 rcc/brca/lung 判別區不同，需不同 skill。用 lung 的 policy 看 esca 會選錯→崩到 0.133→這就是為何需要 NSM。

補充：losses.py 有 l_sem（對齊 CONCH 文字相似度的語義錨），但 N2 這版訓練迴圈只用 cross-entropy，沒開 l_sem。

誠實版：經得起推敲嗎？（含 seq==oneshot 原因）

站得住：CL 軸有乾淨證據；「無標註卻能 navigate」有明確弱監督原理；零件沿用、框架創新的定位誠實。

主動承認的弱點：① Agent 軸 sequential 這版還沒贏 oneshot（報「進行中」）；② 目前只測 esca 單任務、單 fold、test set 小（15 張，顆粒 6.67%）。

seq==oneshot 原因：(a) budget=16、step=16 只有單輪，redundancy 沒啟動；(b) 15 張顆粒太粗；(c) redundancy 權重相對 router 分數尺度太小。是調參/設定問題，不是 bug。 修法：base_score 正規化＋加大 redundancy＋縮小 step，並在大一點的 test set 上測。

二、N3 分析的答辯觀念 · wiki 08
N3 在做什麼？（不重訓）

N2 已把 4 任務 router 訓好、存進 NSM。N3 不重訓，只把同一 skill bank 對 task_index 0/1/2/3 分別 eval（esca/rcc/brca/lung），組出 retention 表＋畫圖。重點從「單看 esca」升級成「看整條任務流的記憶全貌」。

必須懂的 CL 三指標（mACC / Forgetting / BWT）

設 a[i][j] = 學完第 i 個任務後測第 j 個任務的 acc。

  • mACC：全學完後 4 任務 acc 平均。整體好不好。
  • Forgetting（越小越好）：每個舊任務「歷史最佳 − 最終」再平均。量被洗掉多少。
  • BWT（越接近 0/正越好）：mean(最終 − 剛學完當下)。學新對舊是傷害(負)或幫助(正)。

防答辯：nonsm 會出現大 Forgetting / 很負 BWT（esca 0.867→0.133）；nsm 把 Forgetting 壓近 0。對比這兩條就是 N3 主結果。

retention 表 / budget 曲線怎麼讀

retention 表：列＝學到第幾任務，欄＝測哪任務，看下三角。對角線＝剛學完表現；同一欄往下掉＝遺忘。nsm 與 nonsm 兩張並排，一眼看出貢獻。

budget 曲線：x=budget、y=acc。看 acc@K 多快逼近 acc@All（逼越快＝少少 patch 就抓到重點）。同圖疊 sequential vs one-shot；分不開就誠實標「增益待調參」。

為何要 3-fold？成功判準是什麼？

3-fold：esca test 僅 15 張，單 fold 顆粒度 6.67%，易被切分運氣影響。3 fold 取 mean±std 才有統計意義。缺格標 [MISSING]，不捏造。

成功判準（先講好）：主判準(CL) nsm 舊任務 acc 顯著 > nonsm 且 Forgetting 較小（已有 fold-1 強訊號）；次判準(Agent) acc@64 接近 acc@All；探索 sequential 是否 > one-shot（多半打平，列 future）。

三、ZeroSlide 對比 與 老師疑慮 · wiki 09
ZeroSlide 在做什麼？我們輸了嗎？

ZeroSlide 結論：WSI lifelong learning 用凍結病理 VLM 做 zero-shot 分類、吃全部 patch，就能跟需訓練的 CL 打平且天生零遺忘。它把「分類這一軸的 CL」幾乎關掉了。

所以它不是對手，是我們的動機錨點：分類能 zero-shot，那「該看哪 (navigation)」也能 zero-shot 嗎？還是需要 continual navigation learning？

「我們 oneshot 不好＝輸 ZeroSlide」是誤解：它比「全 patch 分類準度」；我們比「budget 下跨任務還記不記得怎麼選」。不同題目。我們的 nsm vs nonsm（0.867 vs 0.133）是在自己題目上贏，不衝突。

★ 老師疑慮①：encode 完才選，budget 還省得到算力嗎？

先承認：現行 encode-all→aggregate 下，encoder 已跑全部 patch，後段聚合 O(n·d) 線性，加 Top-K 幾乎不省時間。以「省 predictor 算力」當主動機站不住，放棄此 framing。

budget 的真正角色（改寫後）：

  • 1. 臨床可稽核 / 可解釋（最主要）：醫師/法規要「短、有序、可驗證的證據鏈」。budget=K 逼出最關鍵 K 個視野＋觀察順序（Navigation Trace）；全 patch heatmap 糊成一片不能稽核。跟省算力無關，是證據要可讀。
  • 2. 下游每-patch 成本高時 K vs n 放大百倍：被選 patch 再餵大型 VLM/LLM、agent 逐 patch 推理、高倍重讀、人工複閱→成本移到下游，budget 變關鍵。agentic pipeline 正是這情境。
  • 3. 指向 select-before-encode 未來設計：先用便宜訊號決定哪些 patch 值得 encode，省最貴的 encoder passes。現在不適用，但本工作鋪路。
  • 4. 臨床直覺：WSI 太大，醫師看到某 pattern 就轉向、不逐格看。budget+sequential 把這形式化。

一句話：budget 不是省算力，是為「可稽核證據鏈」與「下游昂貴觀察」；真正省算力的版本（select-before-encode）是本工作鋪路的未來式。

★ 老師疑慮②：selection forgetting 是 trivial 嗎？

承認：任何 trainable 模組 sequentially train 都會遺忘（如 ResNet 當 CL backbone）。「觀察到遺忘」本身不是貢獻，老師對。

我們的貢獻不是「發現遺忘」，而是：

  • ① 解法：NSM 把 navigation 遺忘救回（0.133→0.867）。
  • ② 問對問題：承 ZeroSlide——分類能 zero-shot 不遺忘了，那 navigation 呢？我們證明 navigation 這臨床關鍵能力不會自動免疫於遺忘，需當成 CL 問題。把 ZeroSlide 的問題延伸到它沒碰、且更要緊的維度。
  • ③ 用詞從「selection forgetting 是新發現」改為「continual navigation：zero-shot navigation 夠不夠？」
★ 釐清：zero-shot navigator ≠ one-shot 的兄弟（2×2 表）

用詞陷阱：zero-shot、one-shot、sequential 都有「shot」，但講兩件事。

★ 主打
  • 橫軸＝一張片內看幾輪（Agent 軸）；縱軸＝選法要不要訓練（訓練軸）。
  • N2 跑的是下排（continual）；zero-shot navigator＝把上排補上。
  • ZeroSlide 本人＝不訓練＋連選都不選（吃全部 patch）＋只做分類 → 在這張表外面更上層（連 budget 都不要）。

同架構換引擎：Observation State / budget / sequential / Gate / NSM 全不動，只換打分來源（router 分數 ↔ CONCH 文字相似度）。不重寫，加一個 policy_mode=zero_shot 分支（SPEC-07）。本身不訓練，只跑一次 inference 評估（esca Mac 即可）。

defend 價值：把老師「為何不 zero-shot」「forgetting 是否 trivial」變成 ablation——continual > zero-shot 就證明訓練+記憶值得；打平就誠實報 + 留強 baseline。

★ 兩種遺忘 + 我們的 zero-shot 跟 ZeroSlide 哪裡一樣 + 誰才是 Agent

哪裡一樣：工具一樣（frozen FM 文字對齊、零訓練），工作不同——ZeroSlide 拿來分類（看全部、不選），我們拿來選 patch（看哪）。我們＝把它的招從分類搬到 navigation。

真的有兩種遺忘（住在會被訓練的模組裡）：

遺忘住哪我們的狀態
classification forgetting分類頭不存在（backbone 凍結）
navigation forgettingrouter唯一存在（只有 router 訓練）

ZeroSlide 對抗哪種？ classification forgetting，解法是「根本不訓練→零遺忘」。它完全沒碰 navigation（看全部、不選）→ 「他們解了 navigation 遺忘、我們輸給他們」不會發生，因為它沒有 navigator。

真正對手＝我們自己的 zero-shot navigator。輸了（打平/更好）也不是末日：等於說「navigation 也不用訓練」，是延伸 ZeroSlide 的可發表發現。即使打平，仍有：

  • ① 可吸收未來訊號（gaze/RLHF/reward）——zero-shot 寫死學不動，有天花板。
  • ② 真正序列/狀態決策——zero-shot 偏 one-shot。
  • ③ 換 backbone 穩健——zero-shot 全靠 FM 文字對齊強。
  • ④ CL 框架本身（NSM/gate/序列觀察）可重用。

誰適合 Agent？continual（可訓練）那邊。 zero-shot＝固定分數＝反射，好 baseline；continual＝可學 policy＝能被 reward 優化、會成長＝Agent 本體。

定位：zero-shot 是「反射式」強 baseline；continual 是「可學的 agent」，是唯一能吸收回饋、真序列決策、不挑 backbone 的路。

由此新增的關鍵 baseline：zero-shot navigation

ZeroSlide 催生一個必須做的對照組：

  • zero-shot navigator：不訓練 router，直接用 frozen backbone 的 CONCH patch-text 相似度選 K 個 patch。天生零遺忘。
  • continual navigator（我們）：trainable router + NSM。

研究問題定版：Is zero-shot navigation enough, or do we need continual navigation learning? 我們 > zero-shot navigator → 證明 learned+記憶的 navigation 有價值；打平 → 誠實報，仍貢獻「navigation 維度的 CL 分析 + 一個強 baseline」。
